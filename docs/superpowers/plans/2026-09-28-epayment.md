> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Port the `feat/payment-gateways` disbursement stack onto `main` (fixing its 3 CRITICALs as we go) and auto-fire a real-time Remita disbursement when an outgoing vendor payment (with bank details) is posted while the tenant e-payment toggle is active — booking to a Gateway Settlement Clearing GL, settled to Bank by the PSP webhook.

Fail-closed everywhere; the `IsApprover('post')+MFA` cash gate is untouched.

**Tech Stack:** Django 5.2 + django-tenants, DRF, pytest-django (`--reuse-db`; posted-journal tests `transaction=True`), React+TS+Vite. Backend port **8032**. Spec: `docs/superpowers/specs/2026-09-28-epayment-design.md`. Deep map of the source branch is the authority for file contents; **verify each ported file's semantic deps against current main before compiling** (`get_vendor_ap_account`, `BasePostingService`, `get_gl_account`, `Payment`/`PaymentVoucherGov`/`Vendor` fields).

**Port convention:** to bring a NEW file, run `git show feat/payment-gateways:<path> > <path>` then `manage.py check`. For a CONFLICT file, read both versions and hand-merge.
```python
def can_disburse_via_gateway(payment) -> bool:
    """Gateway is ONLY for a real vendor payable with bank details — never an
    advance and never a direct/non-invoice PV (those recognise expenditure and
    run appropriation/warrant checks, and have no AP to debit)."""
    vendor = payment.vendor
    if not (vendor and vendor.bank_account_number):
        return False
    if payment.is_advance:
        return False
    if not payment.allocations.exists():
        # a PV with no allocation is a direct/non-invoice PV (salary/pension/etc.)
        return False
    return True
```

Guard `dispatch_payment_via_gateway`: `if not can_disburse_via_gateway(payment): raise GatewayDisbursementError("This payment type cannot be disbursed via gateway.")` at the top.
